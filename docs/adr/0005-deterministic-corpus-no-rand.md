# Production code is deterministic; the corpus is generated, not random

The workspace bans `rand` for production paths and treats determinism as a correctness
property. The synthetic corpus is generated by `tools/corpus-builder`, and the CI
runs it twice and compares bytes. This makes oracle diffs reproducible and keeps
render/parse output stable across runs.

**Consequences**: any new nondeterministic dependency needs an explicit, documented
exception in `deny.toml`. Test fixtures should be seeded or generated, not random.
